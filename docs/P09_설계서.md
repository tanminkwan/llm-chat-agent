# P09 설계서 - 비 로그인 서비스 (Standalone) 모드

## 1. 개요
`llm-chat-agent` 시스템은 보안 및 권한 관리를 위해 OIDC 기반의 IDP(Identity Provider) 연동 로그인을 기본으로 사용합니다. 하지만 외부 네트워크와 단절된 폐쇄망 환경이나 IDP 인프라가 구축되지 않은 로컬 개발/테스트 환경에서는 서버 기동 자체가 제한되는 문제가 발생할 수 있습니다.
이에 본 설계는 환경 변수(`NON_LOGIN_SERVICE`) 설정만으로 시스템 내부의 모든 IDP 의존성을 안전하게 분리하고, 즉시 사용할 수 있는 독립 실행형(Standalone) 모드를 제공하는 아키텍처를 정의합니다.

## 2. 설계 원칙 및 방향
1. **코드 응집도 및 무영향성 (Zero-Impact)**: 비 로그인 모드를 위한 로직을 각 의존성 함수의 최상단(Early Return)에 배치하여, 기존 IDP 로그인 및 토큰 검증 로직에 전혀 영향을 주지 않도록 설계합니다.
2. **시동 의존성 제거 (Boot Isolation)**: 서버 부팅 시점에 발생하는 IDP의 메타데이터(`.well-known/openid-configuration`) 네트워크 통신을 조건부로 차단하여 시스템 기동 안전성을 보장합니다.
3. **편의성 중심의 권한 부여**: 비 로그인 모드일 때는 복잡한 인증 절차 없이, 모든 접근자를 최상위 권한(`nobody / Admin`)으로 인식하여 API 및 시스템 활용 편의성을 극대화합니다.

## 3. 세부 구현 사항

### 3.1 환경 변수 모델 (`libs/core/settings.py`) 수정
- **선택적 환경 변수 전환**: Pydantic `Settings` 클래스에서 필수(Required)로 지정되어 있던 `OIDC_CLIENT_ID`와 `OIDC_CLIENT_SECRET`를 `Optional[str] = None`으로 변경합니다.
- **신규 설정 추가**: `NON_LOGIN_SERVICE: bool = False` 속성을 추가하여 이 모드의 활성화 여부를 전역적으로 통제합니다.

### 3.2 OIDC 클라이언트 등록 및 메타데이터 통신 격리
- `libs/core/auth.py` 및 `apps/api/main.py`에 선언된 `oauth.register('mwm-idp', ...)` 부분은 서버 기동 후 지연 로딩을 통해 IDP의 메타데이터 URL과 통신할 여지가 있습니다.
- 이 부분을 `if not settings.NON_LOGIN_SERVICE:` 조건으로 래핑하여, 비 로그인 서비스 모드에서는 아예 OIDC 클라이언트를 시스템에 등록하지 않도록 원천 차단합니다.

### 3.3 인증 미들웨어 / 의존성(Dependency) 우회
각 모듈에서 사용자 인증을 담당하는 핵심 로직 최상단에 검증 우회 코드를 삽입합니다.

- **API 라우터 (`apps/api/api.py`, `libs/core/auth.py`)**:
  `get_current_user` 함수의 첫 줄에 아래와 같은 분기를 삽입하여, 토큰이나 세션을 검사하지 않고 관리자 객체를 즉시 반환(Early Return)합니다.
  ```python
  if settings.NON_LOGIN_SERVICE:
      return UserInfo(sub="nobody", preferred_username="nobody", groups=["Admin"])
  ```
  (단, `libs/core/auth.py`의 `UserInfo` 생성자는 `username` 인자를 사용하므로 각 클래스 시그니처에 맞게 조정합니다.)

- **UI 라우터 (`apps/api/main.py`)**:
  SPA(Single Page Application) 접근 제어를 담당하는 `_require_user` 함수의 첫 줄에 분기를 삽입합니다.
  ```python
  if settings.NON_LOGIN_SERVICE:
      return None
  ```
  인증 실패 시 발생하는 IDP 리다이렉트를 무효화하고 통과시킵니다.

- **로그인 엔드포인트 방어 (`apps/api/main.py`)**:
  `/auth/login`, `/auth/callback`, `/auth/logout` 경로에 직접 접근하더라도 `NON_LOGIN_SERVICE` 모드에서는 홈(`/`)으로 리다이렉트 처리하여 불필요한 OIDC 에러를 방어합니다.

## 4. 제약 및 보안 사항
- `NON_LOGIN_SERVICE` 기능은 철저히 개발 환경 및 폐쇄망 운영 편의를 위한 백도어 성격의 기능이므로, 반드시 `.env`에서 명시적으로 `True`를 선언할 때만 동작하도록 기본값은 `False`로 고정합니다.
- 이 설정이 켜져 있는 동안 시스템에서 발생한 작업 내역(LLM 로그, RAG 변경 이력 등)은 모두 `nobody`라는 단일 식별자로 기록됩니다.

## 5. 구현 및 테스트 결과
- 위 설계에 따라 `libs/core/settings.py`, `libs/core/auth.py`, `apps/api/main.py`, `apps/api/api.py` 파일의 수정을 완료하였습니다.
- `.env`에 `NON_LOGIN_SERVICE=true` 옵션을 적용한 후 컨테이너를 구동하여, **IDP 메타데이터 통신이 발생하지 않는 것**을 확인했습니다.
- 외부 API 호출 시 HTTP 헤더나 쿠키 등 **아무런 인증 정보 없이도 정상적으로 사용자 정보(`nobody`)와 관리자 설정 정보를 응답**받는 것을 테스트 완료했습니다 (`200 OK`).
