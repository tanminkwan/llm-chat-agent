# P08 설계서 - 하이브리드 REST API 인증 (API Key 위임 검증)

## 1. 개요
`llm-chat-agent`는 기존에 웹 브라우저를 통한 OIDC 로그인 후 세션(Cookie)을 이용한 인증 방식을 사용했습니다. 그러나 외부 스크립트, 연동 서비스, 배치 작업 등 비브라우저 환경에서 API를 호출해야 하는 요구사항이 발생했습니다.
이에 따라, 본 설계는 IDP(`mw_app/idp`) 서비스에서 제공하는 "관리자 REST API Key" 기능을 활용하여 `llm-chat-agent`의 REST API도 동시에 보호(Hybrid Auth)할 수 있는 구조를 제안하고 구현합니다.

## 2. 설계 원칙 및 방향
마이크로서비스 아키텍처 원칙에 따라, 두 시스템(IDP와 llm-chat-agent)은 서로의 데이터베이스를 직접 조회하지 않습니다.

1. **소스 변경의 최소화**: 
   IDP 쪽 소스 코드를 전혀 수정하지 않고, 이미 검증 로직(`@require_api_key`)이 적용되어 있는 가장 가벼운 조회용 엔드포인트를 활용합니다.
2. **이중 인증 체계 (Fallback)**:
   API 요청이 들어왔을 때, `Authorization: Bearer <API_KEY>` 헤더를 최우선으로 검증하고, 실패하거나 없을 경우 기존의 세션(Cookie) 인증을 수행하도록 단일 의존성 주입(`get_current_user`)을 개선합니다.
3. **가벼운 검증 통신 (Zero-Impact)**:
   IDP의 `GET /api/sync/status` API는 내부적으로 데이터베이스 부하 없이 메모리(Config)의 딕셔너리만 반환하는 엔드포인트이므로, 매 API 호출마다 백그라운드로 검증 요청을 보내도 오버헤드가 극히 낮습니다.

## 3. 세부 구현 사항

### 3.1 `get_current_user` 의존성(Dependency) 수정
`apps/api/main.py` 파일의 기존 세션 전용 인증 함수를 아래와 같은 흐름으로 변경했습니다.

- **FastAPI HTTPBearer 도입**: `fastapi.security.HTTPBearer`를 추가하여 표준 Bearer 토큰 헤더를 쉽게 파싱합니다. (`auto_error=False`로 설정하여 토큰이 없어도 403을 뱉지 않고 다음 로직으로 넘어가게 합니다.)
- **Proxy Validation (위임 검증)**:
  - 헤더에 `API_KEY`가 존재하면, 비동기 HTTP 클라이언트(`httpx.AsyncClient`)를 생성합니다.
  - IDP 서버(`OIDC_ISSUER`)의 `/api/sync/status` 엔드포인트로 동일한 Bearer 헤더를 복사하여 백그라운드 요청을 보냅니다.
  - IDP에서 `200 OK`를 응답하면, 해당 API Key가 유효하며 `Admin` 또는 `PowerUser` 권한을 가졌음이 증명된 것입니다.
- **UserInfo Mock 객체 반환**:
  - API Key 통과 시, 기존 로직이 요구하는 `UserInfo` 객체 규격에 맞추어 `groups=["Admin"]`을 가진 가상의 `API Client` 식별용 객체를 생성하여 반환합니다.
- **세션 Fallback**:
  - 헤더가 없거나, 검증에 실패(401/403)하거나, IDP 통신에 문제가 생긴 경우 기존의 `request.session.get('user')`를 통해 브라우저 세션 인증을 시도합니다.

### 3.2 보안 및 고려 사항
- **Timeout 설정**: 백그라운드 IDP 통신 시 무한 대기를 방지하기 위해 `timeout=3.0`을 설정하여 API 응답 지연을 차단합니다.
- **HTTPS 검증 (`verify=False`)**: 로컬/개발 환경에서의 자체 서명 인증서(Self-Signed Certificate)를 사용하는 OIDC_ISSUER 특성상 `httpx` 호출 시 인증서 검증을 무시하도록 설정했습니다. (운영망 전환 시 인증서 체계에 따라 수정 가능)

## 4. 활용 방법
- **UI (웹 브라우저)**: 이전과 동일하게 OIDC 로그인을 거쳐 세션으로 자동 인증됩니다.
- **배치 작업 및 외부 연동 (CLI, cURL, Python 스크립트 등)**:
  IDP 대시보드(Admin Settings)에서 발급받은 `관리자 REST API Key`를 HTTP 헤더에 포함시켜 요청합니다.
  ```http
  POST /api/rag/bulk-upload HTTP/1.1
  Host: llm-agent.mwm.local:21443
  Authorization: Bearer <IDP에서_발급받은_API_KEY>
  ```
